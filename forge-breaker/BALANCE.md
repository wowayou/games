# 难度与调参

## 核心循环与本轮目标

装填双球 → 移动挡板接球 → 锻打叠伤、命中蓄热 → 手动爆发收尾 → 每炉强化、每两炉永久锻造。

原来的压力会互相放大：漏接削掉锻打层数，清场变慢，再装填消耗生命，同时敌人继续推进。固定像素推进速度又让短屏幕的时间更少；每四炉的首领生命和减伤带来突增。

本轮保留接球技巧、双球取舍、手动爆发及完美一轮奖励，默认使用「舒缓」。所有难度参数集中在 `game.js` 顶部 `BALANCE`；菜单可以选择「舒缓 / 标准」，选择只影响新局并独立保存，不修改永久锻造存档。

验收边界：失球后可恢复输出；未发球不推进，重新装填有有限缓冲；手机与桌面的第一排抵达时间一致；长按和重复输入不造成额外付费；暂停不推进缓冲计时；强化和首领流程保持可用。模拟必须报告击杀与泄漏，不能把敌人全部撞进炉心当作成功清场。

## 调参入口

修改 `game.js` 的 `BALANCE` 后刷新页面、开始新局。菜单和结算页均可切换预设。主要分为接球操作、敌人压力、失误恢复、输出成长四组，先调整与问题直接相关的一组，再跑同一组种子对比。

| 参数（`modes` 内） | 舒缓（默认） | 标准 | 作用 |
| --- | ---: | ---: | --- |
| `paddleWidth` / `ballSpeed` | 180 / 620 | 145 / 700 | 初始挡板宽度、球速（像素 / 秒） |
| `freeReloads` / `igniteCost` | 5 / 5 | 3 / 10 | 免费装填次数、额外装填生命代价 |
| `singleLossRetention` / `volleyRetention` | 0.8 / 0.5 | 0.5 / 0 | 单球失误 / 整轮结束的层数保留率，向下取整 |
| `reloadGrace` | 2.5 秒 | 1 秒 | 全部球离场后的推进缓冲；重新发球即结束 |
| `approachSeconds` / `secondsPerWave` / `minApproachSeconds` | 55 / 1.5 / 28 | 43 / 2 / 18 | 首炉抵达时间 / 每炉缩短 / 最短时间 |
| `bossHpBase` / `bossHpPerWave` | 24 / 8 | 40 / 12 | 首领生命 = 基数 + 炉次 × 增量；第 4 炉为 56 / 88 |
| `leakDamage` / `eliteLeakDamage` | 4 / 8 | 5 / 10 | 普通 / 精英撞炉伤害 |
| `hitHeat` / `catchHeat` | 7 / 5 | 4 / 0 | 基础命中 / 接球蓄热 |
| `heatDecay` / `leakHeat` | 0.5 / 10 | 2 / 20 | 每秒散热 / 撞炉损失热度；满热不衰减 |
| `waveHeal` | 最多 8 | 0 | 每炉每击杀一名敌人修复 1 点，受此上限及最大生命限制 |

共同参数：

- `starter`：开局生命、伤害、双球、穿透次数。
- `paddle`：移动跟随速度、键盘速度（720 像素 / 秒）、屏宽上限（65%）。
- `speed`：速度强化每次 +15%，最多 900 像素 / 秒；已到上限的球速、挡板强化不再出现。
- `combat`：锻打上限、每层增伤、连击增伤、爆发系数、额外蓄热、精英与首领减伤。总伤害倍率 = `(1 + 层数 × 0.2) × (1 + 连击 / 45)`，默认锻打最多 25 层。
- `wave`：行列数、行列增长间隔及上限、普通敌人的基础生命及增长。敌人数与生命曲线本轮不降低。

两档都按初始最靠下敌人到炉心的距离计算推进速度。第一枚球发射之前不推进，之后不会因一直不发球而无限暂停；冻结与重装缓冲仍可延长时间。短屏压缩出生区域，旋转时保留敌人的相对推进进度。

标准沿用原有装填、失球和蓄热压力，但也使用新的跨屏推进、输入保护、速度上限和逐炉发球规则，因此不是旧版本的完全复刻。难度预设不按局内表现自动变化。

完美轮次仍要求零泄漏，1 / 2 / 3 次装填分别取得完整 / 一半 / 四分之一矿石奖励；4 次以上免费机会只提供容错。新炉清掉上一炉的球，避免上一炉伤害快照和装填计数混入本炉。热度继续保留；满热时点击、空格、触屏 ⚒ 都优先释放爆发，下一次操作才装填。长按不重复装填。

## 验证与复现

无需 npm 依赖，Node.js 22 或更新版本：

```bash
node --check game.js
node volley-test.mjs
node difficulty-test.mjs
node difficulty-sim.mjs
```

浏览器测试先在仓库根目录启动 `python3 -m http.server 4173`，在本目录运行：

```bash
node smoke.mjs
node deep-smoke.mjs
node ball-physics-test.mjs
node hud-verify.mjs
```

浏览器工具沿用 `cdp.mjs`，需要允许本地端口和 Chromium 进程，`CHROME` / `TARGET` 可覆盖程序和地址。界面截图保存到 `/tmp/forge-*.png`。

`difficulty-sim.mjs [旧版 game.js 路径]` 使用真实 tick、真实生成的三选一强化、零永久强化、固定种子 20261003–20261014。每组 12 局，最多 8 炉；控制器有瞄准误差与 180 / 300 毫秒反应间隔，丢球后 700 毫秒重新装填。桌面 1280×860、手机 390×667；手机瞄准误差按桌面的 55% 设置。所有组都预判落点、满热即爆发，不能代表不熟悉操作的真人。

2026-10-03 对比当前任务开始时的源码与本轮舒缓参数：

| 控制器 | 旧版击杀占比 | 舒缓击杀占比 | 旧版存活通过 8 炉 | 舒缓存活通过 8 炉 |
| --- | ---: | ---: | ---: | ---: |
| 桌面 / 普通误差 | 67.2% | 100% | 1/12 | 12/12 |
| 桌面 / 较大误差 | 74.0% | 99.5% | 1/12 | 12/12 |
| 手机 / 普通误差 | 88.8% | 100% | 7/12 | 12/12 |
| 手机 / 较大误差 | 86.0% | 100% | 6/12 | 12/12 |

击杀占比 = 击杀 /（击杀 + 泄漏）；“通过”只指存活进入第 9 炉，另列击杀占比防止把泄漏误当清场。较大误差偶尔会改变弹道并提高覆盖率，因此不同误差组不一定单调，不能据此给真人划分技术等级。手机战场较窄、弹球往返较短，舒缓模拟前 8 炉约 36–42 秒，桌面约 115–127 秒；屏幕间只统一敌人抵达时间，没有统一清场时间。

机制检查覆盖难度存储、暂停、重装计费、同时丢球、子球、全失后的爆发、跨屏推进、修复边界与强化上限。前 8 炉之外的无尽成长和真人手感仍需实玩反馈；不要把模拟存活率当成玩家通关率。

本轮验证结果：语法检查、球权回归、11 项难度检查、四个浏览器脚本均通过。浏览器确认了难度持久化、强化 / 融合 / 首领流程、球碰撞，以及手机无球时释放爆发不扣装填费用；人工核对桌面与 390×667 手机截图，菜单与开始按钮可见。最后一次界面回归使用独立端口 41083（通过 `TARGET` 指定）。
